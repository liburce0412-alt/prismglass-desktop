# PrismGlass Desktop 软件整合与开源发布方案

日期：2026-10-27
状态：用户已于 2026-10-27 授权推送并发布首个公开测试版。本文保留完整产品化目标；本次实际完成范围、未实测项和已知限制以对应 Release 与 [验证概述](VALIDATION.md) 为准，不能把整份方案当成已完成清单。

## 已确定的发布方式

PrismGlass 定位为免费、开源的 Windows 桌面软件。继续使用现有公开仓库 [liburce0412-alt/prismglass-desktop](https://github.com/liburce0412-alt/prismglass-desktop)，沿用项目现有 MIT 许可；第三方组件保留各自许可和声明。此前“暂不开放全部源码”的设想已由用户最新决定替代。

同一仓库提供源码、构建说明、问题反馈和 Releases 下载。正式发行的安装包应能追溯到同一个标签对应的源码提交；源码开放不包括开发者的个人配置、账号、配对密钥、证书私钥、私人素材和本机诊断记录。

当前已开始执行源码整理、安装器构建与公开测试版准备。源码提交/推送、安装包公开发布和真实环境结果分别记录。

推荐交付一个 `PrismGlass-Setup-<版本>-x64.exe`，用户下载后通过安装向导完成安装，日常从开始菜单或托盘使用。候选首个软件测试版名称为 `v0.9.0-beta.1`，只是命名建议，不是现有版本或发布日期。面向 Windows 10/11 x64 设计，公开说明分别列出目标环境、已检查范围和仍待用户反馈的兼容性；不能宣称所有电脑均已验证，也不能直接扩写为 ARM64、macOS 或原生 iPad 支持。

本文按完整软件的组成列出同一发布范围，不划分功能批次。按通用软件方向设计，在现有条件下检查，通过后续实际使用反馈持续完善；不以新增电脑、显示器、设备、网络或另找测试人员作为发布前提。伴随屏修改完成后，按届时实际功能更新检查范围，不把开发中的界面提前当成最终发布承诺。

## 整合后的使用体验

普通用户的操作路径为：下载 → 安装 → 选择开启的组件 → 进入桌面 → 在统一设置中调整 → 从托盘退出或更新。构建命令和 PowerShell 参数留给开发者说明，日常使用无需输入命令。

- 保留现有液态玻璃材质、Sky/Astro、应用分类与搜索、Dock、歌词、桌面组件和生态瓶。复用 C# WinForms、WebView2、WebGL 与 Rainmeter，不为安装包重写已经工作的渲染架构。
- 软件有统一名称、图标、版本号和关于页；开始菜单入口、设置、托盘、退出、故障恢复都能找到。
- 默认仍为手动开启美化；安装完成不直接隐藏任务栏或替换壁纸。开机启动是用户可选项，升级不能擅自更改。
- 首次扫描本机应用并整理分类，用户手动分类优先；不携带开发者的应用列表、固定项目或路径。
- 天气位置由用户选择；在线歌词、账号额度和局域网伴随屏保留独立开关与说明，不因安装而自动开启。
- iPad 伴随屏属于软件的可选功能，沿用 Safari/添加到主屏幕的入口，不要求另做 iPad 原生应用。桌面与伴随屏使用相同应用控制逻辑和共享设置规则。

## 安装器与运行依赖

推荐使用 Inno Setup 生成单个 Windows 安装程序，复用现有安装逻辑，并让现有主程序承担统一入口和运行状态管理。它已提供单 EXE 分发、用户级安装、快捷方式、卸载与签名支持，不需要另开发一套安装界面框架。具体版本与许可在制作安装器时锁定并记录。[Inno Setup 功能](https://jrsoftware.org/isinfo.php)、[官方许可](https://jrsoftware.org/files/is/license.txt)。

| 依赖 | 推荐处理方式 |
|---|---|
| WebView2 Runtime | 检测已有 Evergreen Runtime；缺失时由安装器说明并调用官方引导安装。SDK DLL 不能代替 Runtime。下载失败能重试并给出官方离线安装入口，不留下“安装成功但打不开”的状态。依据 [Microsoft 分发文档](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)。 |
| Rainmeter | 复用兼容的现有安装；缺失时引导安装官方发行版，保持独立进程与独立产品身份。识别真实皮肤目录，只管理 PrismGlass 自己的皮肤，不覆盖其他主题。若随包分发，需随具体版本提供其许可要求的材料；上游使用 GPL-2.0，不能套用本项目 MIT。[上游仓库与许可](https://github.com/rainmeter/rainmeter)。 |
| PowerShell 7 | 复用已安装版本，缺失时引导官方安装；短期保留验证过的脚本，安装和启动由软件调度。不要为了看起来只有一个 EXE 而同时重写所有运行逻辑。 |
| Windows PowerShell 5.1 | 仅保留现有 SMTC 读取器的兼容用途，在开发说明中注明。 |
| Rainmeter 插件 | 按实际启用面板检测 PowerPlugin、Win7AudioPlugin、EasyBlur 等引用；区分随 Rainmeter 提供和需额外配置的组件，不能把所有引用都当成必缺依赖。缺少可选插件不应阻止核心桌面运行。 |
| Python / Codex CLI | 只服务现有可选集成，普通桌面安装不要求安装或登录。Node.js 仅用于开发检查。 |

现有运行脚本会通过 `Add-Type` 加载 `DesktopIcons.cs`。开源发行可以暂时保留这个必要文件；如果以后精简安装内容，必须先把对应功能纳入编译程序，不能直接删除后破坏恢复功能。

## 程序、配置与旧版升级

推荐新安装将程序放在 `%LOCALAPPDATA%\Programs\PrismGlass`，用户数据放在 `%LOCALAPPDATA%\PrismGlass` 下的明确数据目录。保留自定义安装路径能力；大量可重建构建缓存可使用已有 D: 缓存，不为改变盘符搬动用户项目或现有安装。

当前旧安装可能位于其他目录，不能只根据默认路径判断。升级应识别启动入口、安装记录和配置文件，必要时让用户选择旧目录，避免在旁边建立另一套运行实例。

需要保留并验证的数据包括：应用库与分类、Dock 固定与排序、各屏布局、歌词设置、主题、笔记与待办、生态瓶进度、伴随屏设备权限与配对。日志、图标和封面等缓存可重建，但不能把它们和用户创建的内容一起清空。

迁移在程序退出后执行，先校验旧文件，再生成新版本；遇到坏配置保留原文件并报告。涉及不可逆格式变化时保留一次必要恢复副本，成功后按规则清理。版本回退必须与配置格式兼容，不允许旧程序用默认设置覆盖新格式。

同一台电脑的伴随屏升级应尽量保留设备身份、固定名称、证书信任和配对；跨电脑或跨 Windows 用户不承诺直接复制受 DPAPI 保护的数据，需要重新建立信任。详情需以伴随屏最终实现为准。

构建输出绝不指向用户正在使用的安装目录：当前 `Build.ps1` 会生成默认壁纸并重写 `pins.json`、`theme.txt`、`paused.txt`，这是发行样例，不是升级策略。

## 卸载、异常恢复与伴随屏生命周期

卸载入口出现在 Windows“已安装的应用”，先有序停止本安装的进程和皮肤，恢复美化前的桌面状态，再删除归属于该安装的程序文件。默认保留个人数据，并明确提供删除个人数据的选项。

不卸载其他软件可能共用的 WebView2、PowerShell 或 Rainmeter，不关闭其他 Rainmeter 皮肤。恢复逻辑要区分本软件临时改变的状态与用户原本隐藏任务栏/图标的偏好，并验证 Explorer 重启、进程崩溃和重启后的结果。

伴随屏的局域网端口、防火墙、URL ACL、证书和固定名称配置必须有安装归属记录。用户首次开启时说明并确认所需系统变更，日常桌面使用不因此要求提权。修复和卸载仅处理本软件创建且仍归属本安装的项目，不删除共享根证书或范围更大的网络规则。

伴随屏当前仍在改动；连接、权限、触控、音乐、扫码等最终验收清单从完成后的实际代码提取。不得把本机 IP、固定设备名、已批准的配对记录或证书带进通用安装包。

## 开源仓库与发行流水线

保持一个仓库，源码、文档、测试和安装定义一起维护。MIT 继续覆盖本项目原创代码；依赖、引用数据及素材的许可仍以 [第三方声明](../THIRD-PARTY-NOTICES.md) 和各许可文件为准。原项目许可不授予第三方歌词、音乐、壁纸或品牌素材的再分发权。

准备公开的提交应只包含产品源码、必要脚本、测试、构建配置、许可与审核过的文档素材。`outputs/`、构建缓存、运行目录、完整本机诊断、私人截图、配对数据库和私钥不进入提交。先检查现有 `.gitignore` 的覆盖范围，再明确选择提交文件，不能直接把全部工作区改动作为发行内容。

发布构建使用干净签出和明确文件清单，锁定依赖版本，并验证来源。主程序、安装器、关于页和更新说明使用同一版本；制品记录提交号、依赖版本、构建环境及校验值。开源后安装包仍只携带运行必要文件，不需要包含开发缓存和测试产物。

GitHub Actions 保留普通推送/PR 的检查与构建；公开安装包增加人工触发或明确批准的发布入口，普通功能提交不自动变成正式发布。代码签名私钥留在受保护的签名环境，不能随开源源码公开。

建议 Release 包含：

- `PrismGlass-Setup-<版本>-x64.exe`。
- `SHA256SUMS.txt`、版本说明、已知问题和测试系统矩阵。
- 项目许可、第三方声明与隐私说明，安装后也能查看。

标签指向实际用于构建的源码提交。GitHub Release 会自动提供对应标签的源码 ZIP/TAR，因此不另维护一套与代码可能不一致的手工源码包。[GitHub Releases 说明](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)。

稳定公开分发建议签署安装器与可执行文件，并验证签名和下载后文件完整性。签名证书的主体和成本在实际采购前确认；没有签名时明确标注未签名测试包，不把校验值当成发布者身份认证，也不承诺签名后一定没有系统提示。

软件内先提供“检查更新 → 打开对应 Release → 用户运行新版安装器”的完整路径，复用同一升级流程，不新增常驻更新服务。安装器负责版本比较和保留数据，不把下载一个新 ZIP 称为自动升级。

## 当前条件下的检查与覆盖范围

后续执行时保留源码检查、依赖与路径检查、隔离构建及现有设备能够完成的运行检查。不同电脑、多屏组合、新设备和新网络目前没有额外实测条件，记录为“未实测”，由将来的实际使用反馈逐步覆盖，不要求为了完成清单增加设备或安排测试人员。本节列出设计要求，实际执行结果以本次 Release 和验证概述为准。

| 场景 | 当前可做的检查与目标 | 尚未覆盖时的记录方式 |
|---|---|---|
| 安装与运行依赖 | 核对依赖检测、下载失败处理、必要运行文件和路径解析；从源码在独立输出目录构建，不复用日常安装目录或开发者配置 | 干净 Windows、其他用户目录和权限组合未实测时如实标注；隔离构建不能写成干净系统安装成功 |
| 现有用户升级 | 检查迁移与回退逻辑；在具备条件的隔离配置或现有设备上确认单实例、配置保留和失败恢复，不能为检查直接覆盖重要用户数据 | 未运行的旧版本迁移路径标为未实测；新反馈注明来源版本与目标版本 |
| 卸载与恢复 | 核对安装归属、恢复原偏好及保留共享依赖的逻辑；使用现有环境可执行的检查确认程序退出和桌面恢复 | 未覆盖的 Explorer/系统组合由后续反馈补充，不把源码检查称为运行验证 |
| 显示器与 DPI | 按每块屏幕的坐标、工作区和缩放设计，检查不相邻、负坐标及不同尺寸的处理；只对当前具备条件的显示环境记录实际结果 | 其他双屏组合、物理热插拔和缩放切换标为未实测；参数检查或拓扑模拟不冒充硬件实测 |
| Dock、歌词与应用控制 | 在现有环境检查连续往返、快速反向切换、悬停标题、应用启动/激活/最小化/恢复及多窗口预览 | 记录实际应用和版本；不能将某个应用可用扩写为所有应用已验证 |
| 性能与长期运行 | 在同一机器、同类场景比较稳定基线与候选版，记录可获得的 CPU、GPU、内存、帧耗时及输入停顿；已确认的性能退化继续修复，保留现有材质效果 | 写明观察时长和环境；其他硬件及长期使用由用户反馈补充，不规定必须完成额外多屏或固定时长实测 |
| 媒体与可选功能 | 核对缺少播放器、联网服务或可选工具时的降级；在现有播放器检查标题、进度、换曲和暂停 | 其他播放器和版本标为未实测，可选服务失败不应阻断核心桌面 |
| iPad 伴随屏 | 待修改完成后检查连接、配对、权限、停用和恢复逻辑；现有设备能查的项目据实记录，未开启时不监听局域网，不因其不可用影响桌面 | 新设备、不同家庭网络、换网和触控等未做的项目保留未实测状态，通过后续反馈补充；不强制重新配置现有网络或配对来凑验收 |
| 开源与发行内容 | 检查干净签出和明确清单能够生成候选包；文件与对应提交一致，不包含个人状态、私钥或无再分发依据的素材 | 只为实际完成的检查记录结果，README 和界面明确剩余兼容性范围 |

检查记录采用三种状态：**已检查**写明版本、方法、环境和结果，并区分静态检查、构建与本机运行；**未实测**说明尚未覆盖的设备或场景；**反馈待确认**保留用户报告和待核对内容。未实测不等于失败，收到反馈也不自动等于已确认缺陷。已有可靠记录可在代码和相关条件未变化时复用，变化后只复查受影响部分。

## 面向其他用户的通用设计

目标仍是其他用户仅凭安装包与公开说明，能够完成安装、主要功能使用、退出、升级和卸载。先保证设计和现有条件下可检查的内容不依赖开发者环境，再根据实际使用完善；不以已有开发机结果保证所有电脑可用，也不设置独立参与者或额外设备的硬性门槛。

| 设计对象 | 要求与后续反馈关注点 |
|---|---|
| 没有开发环境的电脑 | 普通安装不要求 Git、Node.js、Visual Studio、Python、Codex 或开发者缓存。Rainmeter、PowerShell 7、WebView2 缺失时由安装流程检测并引导补齐；检查文件清单和依赖分支，其他电脑安装结果据反馈确认。 |

## GitHub Issues 反馈与迭代

将来经授权提供软件后，沿用现有仓库的 GitHub Issues 收集问题；在使用说明和关于页规划明确入口，不另设强制测试流程。建议问题模板只要求：

- 软件版本；安装或升级问题补充来源版本。
- Windows 版本，以及显示器数量、分辨率和缩放；仅填写与问题有关的信息。
- 复现步骤和出现频率。
- 预期结果与实际结果；截图可选。
- 可选的脱敏日志，不要求上传完整配置或整个运行目录。

默认不自动上传遥测或诊断。用户自愿提交的截图与日志需能先查看并去除私人信息；公开 Issue 不包含私人笔记、待办内容、账号凭据、配对密钥、证书私钥或完整设备授权文件。先将报告记为“反馈待确认”，核对版本和复现条件；确认后修复，并记录修复版本及本地复查结果。用户的后续确认可补充兼容性记录，不把没有回复视为已经修好。

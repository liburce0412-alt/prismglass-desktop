# Safari 内投屏与独立副屏

本文说明 2.0.1 的使用方式与限制。后半部分按日期保留历史验收记录。
在 PrismGlass 伴随屏的「投屏 / 触控」页选择用途：

- **投屏**：选择电脑主屏或其他有线屏幕，以及 720p / 1080p，再点击「开始投屏」。列表不包含 iPad 虚拟屏和无线显示器；处于复制模式的实体屏共享同一画面，只列出一个来源。
- **独立副屏**：点击「打开副屏」后才启用 iPad 虚拟桌面并传输画面；需要另行安装受支持的 MttVDD / Virtual Display Driver。停止、离开页面、撤销授权、锁屏或心跳超时后关闭虚拟屏，不让它在未使用时长期占据 Windows 扩展桌面。切换模式会先停止原会话，再重新读取屏幕。

以上双模式行为从 0.9.2 提供，0.9.1 仅有显示器选择。新版启动会清理已配置投屏安装中的旧版常驻虚拟屏或异常退出残留。仅操作被严格识别的虚拟显示目标，不自动安装驱动、不切换所有屏幕的复制/扩展方式。切换时保存普通桌面图标位置，随后恢复仍在当前物理屏范围内的已有图标；恢复失败时保留本地恢复记录。

2026-11-03 本地修复补充了空闲时重试：启动阶段清理失败后，桌面运行期间每约 5 秒再次检查。正在开始、运行或清理投屏时跳过；锁屏时不执行，也不会关闭唯一的活动显示器。本机更新前后均为 0 个活动虚拟屏，实体屏布局与时序一致；失败后重试及活动会话保护已通过隔离检查，尚未重新执行真实重启和 iPad 启停验收。这项修复已纳入 1.1.1 安装包。

2026-11-05 本地修复增加可选的设备停用：MttVDD 25.7.23 即使没有活动扩展桌面，也会保留一个已检测到的虚拟显示器。新开关在独立副屏开始前启用设备，停止或空闲恢复时停用；切换前后仍校验实体屏配置并保存、恢复图标位置。需要先以当前桌面账户的管理员身份运行安装目录中的配置脚本；不加 `-Apply` 只显示配置范围：

```powershell
pwsh -NoProfile -File .\ConfigureCompanionVirtualDevice.ps1 -AppRoot .\LiquidDesktop
pwsh -NoProfile -File .\ConfigureCompanionVirtualDevice.ps1 -AppRoot .\LiquidDesktop -Apply
```

使用另一管理员账户配置时，必须通过 `-UserSid` 指定实际桌面用户的 SID。脚本只为该用户创建两个可按需运行的 SYSTEM 任务，固定调用 Windows 系统目录的 `pnputil.exe`，仅启停 `Root\MttVDD`；不安装驱动，不添加自动触发器，不以管理员权限运行用户可修改的脚本。应用中止时留下的设备状态由下次启动或空闲恢复处理。配置标记位于 `LiquidDesktop/runtime-data/companion/virtual-device-managed.json`；未配置时保持原有的桌面拓扑清理方式。当前已完成构建、隔离生命周期检查、本机原位更新和管理员配置，已读回固定任务范围与用户只读/运行权限。用户要求自行进行真实启停和多屏体验验收，因此尚未宣称 Windows 显示设置或 iPad 启停通过；此变更尚未公开发布。

播放后画面默认按原比例使用页面可用空间，也可显式选择“拉伸铺满”；不为工具栏固定预留一列。主屏画面下方有足够留白时，按钮放在留白中；独立副屏使用右上角按钮。顶部至少保留 24 CSS 像素，系统安全区更大时跟随系统，避免与 iPad 状态栏重叠。画质、屏幕选择和按键面板按需展开，停止后恢复普通排布。

键盘按钮直接调用原生输入法。右侧天然留白至少 260 像素时，输入区放在右下方，画面保留全部可用高度；其余情况使用约 55 像素的底部输入条，画面靠左下显示，底边贴合输入条上沿。布局跟随原生键盘高度及 Safari 视口偏移，草稿和中文选词焦点保留，发送错误会显示。收起后恢复靠左上方。网页布局不修改实体屏分辨率。操作方式可选触控板、直接点选与拖动、原生触摸（双指）；后两者将画面坐标映射到所选桌面，原生触摸的长按、滚动和缩放由目标应用支持。

## 电脑端准备

### 下载与安装路径

已有可用工具可以直接复用，不要求搬动。下面是建议的可移动工具目录；没有 D 盘时可改为自己的非系统工具目录，并在配置中填写真实路径。

| 组件 | 官方入口与操作 | 建议文件位置 |
|---|---|---|
| FFmpeg | [FFmpeg 下载页](https://ffmpeg.org/download.html) → Windows → gyan.dev 的 Windows full build，解压整个目录并保留配套文件 | `D:\Tools\PrismGlass\ffmpeg\bin\ffmpeg.exe` |
| MediaMTX 1.21.4 | [Windows amd64 ZIP](https://github.com/bluenviron/mediamtx/releases/download/v1.21.4/mediamtx_v1.21.4_windows_amd64.zip)，按 [官方校验文件](https://github.com/bluenviron/mediamtx/releases/download/v1.21.4/checksums.sha256) 核对后解压 | `D:\Tools\PrismGlass\mediamtx\mediamtx.exe` |
| NVIDIA NVENC | 是兼容 NVIDIA GPU 的硬件编码能力，不是单独可安装的程序；安装适用显卡驱动，并检查 FFmpeg 的 `h264_nvenc`。参见 [NVIDIA 官方说明](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.1/ffmpeg-with-nvidia-gpu/index.html) | 不需要填写单独的编码器路径 |

不需要把这些目录加入系统 PATH，也不要手动启动 MediaMTX。PrismGlass 在开始投屏后启动它们，并在停止时清理所属进程。源码与安装包不附带这些工具或驱动。

默认安装的投屏配置文件位于：

```text
%LOCALAPPDATA%\PrismGlass\LiquidDesktop\runtime-data\companion\screen-stream.json
```

若安装时选了其他位置，则使用 `<PrismGlass安装目录>\LiquidDesktop\runtime-data\companion\screen-stream.json`。按下面的 JSON 创建或编辑这个文件，填写真实工具路径，不要把文件存成 `.json.txt`。0.9.2 起，视频通道直接使用已开启的伴随屏 HTTPS 连接所绑定的本机地址；旧配置中的 `address` 可以保留，不会覆盖当前连接。可先在 PowerShell 中检查：

```powershell
& 'D:\Tools\PrismGlass\ffmpeg\bin\ffmpeg.exe' -hide_banner -encoders | Select-String 'h264_nvenc'
& 'D:\Tools\PrismGlass\mediamtx\mediamtx.exe' --version
```

列出 `h264_nvenc` 只说明该构建包含编码器，不代表显卡与驱动已经可用；首次启动投屏仍需验证。完整配置还包括下文的局域网规则和设备授权，解压文件本身不会开启屏幕共享。

- 复用现有 HTTPS 9443、设备配对、Origin/CSRF 校验。
- FFmpeg 需要 `h264_nvenc`，电脑需要兼容 NVIDIA 编码器。当前实现没有软件编码或其他 GPU 的回退。
- MediaMTX 1.21.4；从官方发布页取得 Windows amd64 包并核对官方 SHA256。二进制不随仓库分发。
- 本地安装的 `runtime-data/companion/screen-stream.json` 使用下列结构，填入工具的绝对路径：

```json
{
  "enabled": true,
  "ffmpeg": "D:\\Tools\\PrismGlass\\ffmpeg\\bin\\ffmpeg.exe",
  "mediamtx": "D:\\Tools\\PrismGlass\\mediamtx\\mediamtx.exe"
}
```

视频使用当前连接地址的 **UDP 31890**。0.9.2 起，换网后电脑点「检查并连接」，iPad 打开页面并点「开始投屏 / 打开副屏」。程序只从通过配对、屏幕权限和会话校验的实际请求读取 iPad 地址；需要建立或更新规则时，电脑显示新旧地址及范围，由你确认并通过 Windows 管理员提示。修复完成后 iPad 自动继续连接，无需编辑 IP 或运行命令；等待最多两分钟，可随时停止。已有规则正确时不提示修改。电脑管理页显示检查、等待确认、等待管理员和验证结果；取消或失败后可重新开始投屏，新尝试不会复用上一轮失败结果。管理员进程没有返回具体失败原因时，界面会如实说明。

修复限定为配置中的 MediaMTX、当前专用网卡、电脑地址、同网段的这一台 iPad 和 UDP 31890。升级 MediaMTX 改变路径时，电脑确认窗口会显示新旧程序路径。只有归属当前安装且范围符合要求的规则才可迁移，验证失败会恢复原规则。现有投屏未结束时，其他设备不能抢改它的规则。命令行 `RepairCompanionVideo.ps1 -AppRoot <安装目录\LiquidDesktop> -Address <电脑地址> -PeerAddress <iPad地址>` 默认只读检查，普通用户可沿用软件内确认流程。RTSP/WHEP 诊断工具仍可使用配置中的回环地址，正式伴随屏沿用当前选定的网卡。

2026-11-03 本地修复：视频规则的归属说明曾使用 `|` 分隔符，违反 [Windows 防火墙规则的 Description 字段约束](https://learn.microsoft.com/en-us/windows/win32/api/netfw/nn-netfw-inetfwrule)，导致换网更新时报“值不在预期的范围内”并回滚。改用允许的分隔符后，本机 Windows PowerShell 5.1 已实际完成旧单设备规则迁移，复查确认无需再次申请更新；26 项隔离回归通过。用户从 iPad 重新开始投屏后确认画面恢复。修复脚本已原位更新，并纳入 1.1.1 安装包。

RTSP 31854 与 WHEP 31889 只绑定 `127.0.0.1`，不用开放防火墙。没有外部 STUN/TURN、路由器端口映射或中继；视频会占用局域网带宽，不是零数据传输。

在电脑管理窗为已有设备另行勾选「屏幕画面（投屏）」并保存。原有配对和其他权限保留，新增屏幕权限默认关闭。鼠标控制由「鼠标触控板」、文字与按键由「键盘输入」分别授权，默认关闭。

启用触控后点击「键盘」，会直接聚焦 HTML 输入框以调用 iPad 原生键盘。中文选词在 iPad 完成，点击「发送」后以 Unicode 输入电脑当前窗口；每次最多 1024 个 UTF-16 单元，emoji 可占多个单元，暂不支持段落，也不自动补回车。常用按键有 Enter、退格、方向键、Tab、Esc、全选、复制、粘贴、撤销及切换窗口。发送失败不自动重试；短暂网络失败的草稿仅保留在页面内存，恢复同一授权会话后可核对，撤权或会话身份变化会清理。不读取或同步电脑剪贴板。

## 行为与边界

- H.264 Baseline、30 fps 目标，720p 约 6 Mbps、1080p 约 10 Mbps；电脑系统声音使用另行授权的 Opus / WebRTC 通道，包含其他应用和通知声音，不采集麦克风。
- 捕获所选**整块显示器**，包含其通知和其他窗口；不提供单软件隔离。
- 仅点击开始后启动采集与路由进程；一个观看者。停止、权限撤销、Windows 锁定、网页离开或隐藏都会停止；失联心跳最多 15 秒过期。
- 子进程归入带关闭清理的 Windows Job。伴随屏维持运行时，单独退出 PrismGlass 桌面可以继续已有投屏。主动停止、撤权、锁定、失联或宿主进程退出仍会结束采集。
- 仅共享获准内容；网页与浏览器资源清理不会清除用户配对和小组件偏好。

## 本地体验打磨增量（2026-10-31，已安装本机预览，未发布）

- “保持比例 / 拉伸铺满”仅改变网页显示，不改变实体屏配置；自然留边提供触控、输入与窗口、编辑三组操作。
- “直接点选与拖动”支持轻点目标和按住移动；滚动使用右侧滚动条或触控板。服务端在有效画面租约内重新检查采集边界，支持负坐标，先定位按下再移动、松开。画面布局变化、模式切换或第二根手指介入会取消拖动；迟到坐标不重放，失去拖动续期后最多 750 毫秒释放。它仍是鼠标输入，不代表 Windows 原生多点触摸。

- “外接键盘直输”需显式开启并聚焦画面；支持普通单字符、已有编辑键与 Ctrl+A/C/V/Z；Shift+Tab 回本地控件。浏览器截获的组合键不承诺透传，中文软键盘仍手动发送。
- 文字上限为 1024 UTF-16 单元（emoji 可占多个单元），请求体同步有界扩容；500 中文、标点与 emoji 已通过隔离传输测试。仍拒绝换行，不替换为电脑 Enter，实际应用长文本与多行尚未验收。
- 同一投屏在 ICE 短暂断连时等待最多 6 秒；单次网络 ping 失败只重试一次，明确失效或撤权立即结束。恢复期间画面变暗并停止输入，主动停止后不自动重开。
- 保留来源选择；进程身份变化或来源消失要求重新选择，避免旧数字 ID 换屏。网络失败文字仅存在页面内存并隐藏，恢复同一授权会话且键盘权限仍有效时可核对；不自动重发。CSRF 会话轮换会保守丢弃旧草稿。

## 本地系统声音与文字实验（2026-10-31，未发布）

在电脑设备权限中明确勾选“电脑系统声音（含其他应用与通知）”，保存后重新开始投屏，再点“开启声音”。旧设备授权默认关闭声音。采集来自 Windows 默认播放设备，不请求 iPad 麦克风。若 Safari 阻止有声播放，点“点按播放声音”；单独关闭声音或音频失败不关闭视频。音频使用独立 WebRTC 连接，输出设备变化会停止声音并提示重开。灵动岛显示实际声音共享状态。

声音请求具有递增顺序与 12 秒连接期限；迟到开启不能覆盖关闭，旧关闭不能结束新连接。每次视频心跳同时确认声音意图；失去声音续期后最多 15 秒清理采集。停止投屏、离页、锁定或撤权沿用整个会话的清理。电脑音量仍控制电脑输出，iPad 音量键控制 iPad 播放；未实现“仅 iPad 出声”。

本机测试已验证 2 秒真实回环 PCM、Opus 编码、WebView2 收到非静音解码音频、视频同时解码、关闭音频后视频继续及最终进程清理。测试使用环回地址和静音接收分析器，未保存声音文件；不能代替 iPad 外放、Safari 播放策略、音画同步、耳机切换和长期稳定性验收。

500 字中文、标点和 emoji 在 Windows 编辑框及 Chromium textarea 均完整接收。Unicode LF 在 Windows 编辑框变为段落，在 Chromium textarea 中被忽略，因此继续保留单行手动发送，不将 LF 替换为电脑 Enter，也不改写用户剪贴板。

本轮 iPad Air 2 / iPadOS 14.2 USB 实测：Safari 播放 1280×720，表单发送的 500 字中文、标点和 emoji 在专用 Windows 窗口逐字相同；样本由调试接口填入，不代表原生输入法组词通过。声音轨已收到，Safari 首次播放提示需要点按，用户点按后确认听到系统声音。完整记录及一次启动失败、一次声音关闭的未定原因见仓库中的 `docs/VALIDATION.md`。

停止投屏或副屏会同时停止这台设备的触控，并松开正在拖动的鼠标；重新控制前需再次启用触控。失联由电脑端超时清理。若指针被 Windows 的触摸输入抑制，释放按钮后恢复到原位置；不更换电脑指针主题。此行为的 Windows 原生检查已通过，本轮 iPad 退出效果仍待确认。

### 原生触摸接入（2026-10-31，本地预览）

投屏操作方式新增“原生触摸（双指）”，保留触控板和直接点选。此模式把最多两个触点送入 Windows 触摸接口，长按、滚动与缩放由目标应用支持。来源与坐标沿用实时投屏校验；250 ms 完整触点更新维持长按，750 ms 无更新时取消。切换方式、画面变化、第三指、系统取消或断线会释放触点；取消时不会补发鼠标点击。Windows 已经取消整组触点时，重复取消按已释放处理，避免阻止后续重新控制；普通按下或移动失败仍按错误处理。不能兼容触摸的软件可改用直接点选或触控板。

本轮用户已确认 iPad 点按、长按、双指缩放有效；电脑专用浏览器观察到最多两个同时触点、长按菜单和缩放变化。用户另确认系统中文组词、删改和手动发送正常。中文连续自动输入仍保留方案规定的手动发送保底；这不代表任意软件都支持触摸手势或通用多行输入。

电脑端 WebView2 两分钟音视频连续解码、关闭声音保持视频、重新开启声音、采集进程意外退出后重开和最终清理通过；没有录音文件。另在当前 Realtek 输出端点短暂静音，系统回环仍收到合成声音，随后恢复原静音、音量及默认输出；这是当前端点的电脑侧证据，不代表所有设备或“仅 iPad 出声”完整验收。

采集改用事件驱动和更小的有界缓冲，编码输入采用 10 ms WAV 分包。测量器改为在音轨到达时立即接入分析，排除了晚接收音轨带来的积压；旧的约 510 ms 首次测量不能据此归因产品。校正后三轮电脑端合成闪光/声音测量的时差范围为 80–150 ms，最终七次（含启动）为 80、119、131、131、149、150、150 ms，声音晚于视频。测量包含源播放与浏览器轮询误差，不代表 Safari 或实体扬声器延迟。iPad 音画同步、耳机切换及长期稳定性仍待设备验收；当前用户选择只继续电脑端检查。

全屏投屏和键盘输入模式顶部保留至少 24 CSS 像素；系统安全区更大时跟随系统。画面、触控区域和控制按钮一起下移，保持比例/拉伸与键盘布局均使用剩余空间，顶部留白不会向电脑发送触控。

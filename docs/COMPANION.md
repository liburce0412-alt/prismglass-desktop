# iPad 网页伴随屏

已在 iPad Air 2 / iPadOS 14.2 Safari 验证基础连接、投屏全屏和原生中文键盘；这不代表全部功能或其他设备均已验证。各层检查与未实测范围见 [公开验证概述](VALIDATION.md)。

伴随屏随 PrismGlass 主进程运行，每次由托盘菜单或电脑设置中的 **iPad 伴随屏** 手动开启。不会新增开机启动、安装 iPad App、运行另一套 Node/Python 服务，本身不会创建 Windows 扩展显示器；可选投屏能选择另行安装并启用的虚拟显示器。

桌面外观设置、歌词效果同步、触控手势、小组件和控制中心的源码检查、安装与真实设备结果分别记录，见 [公开验证概述](VALIDATION.md)。此前扫码与主页确认不覆盖全部新增功能。

## 功能与共享

- Sky / Astro 配色沿用电脑偏好。新版以低对比蓝灰柔光远景为背景，分为此刻、触控板、工作、应用、小组件和电脑视图，笔记提供独立编辑区。主页优先呈现时钟和当前音乐；没有内容的模块收起。Touch Bar 独占底部区域，不覆盖编辑区。
- Touch Bar 默认跟随电脑前台应用，也可固定通用、浏览器、编辑器、音乐或专注场景。Chrome / Edge 支持后退、前进、刷新、新标签及标签切换；VS Code 支持命令面板、打开文件、查找及侧边栏。其他应用提供通用控制。固定场景不会切换电脑窗口；应用快捷键在执行前再次核对前台身份，已切换时拒绝旧请求。仅传已支持应用的名称和随机上下文 ID，不读取窗口标题或内容。
- 应用每页 24 项，分类和搜索在本页内存筛选；图标最多 3 个并行请求，同会话复用内存图片。退出、锁屏、隐藏页面或断开后清除并释放图片，不写离线缓存。
- 图片和核心 API 使用独立额度和并发槽。并发忙返回 1 秒重试；次数限流按服务端剩余窗口冷却，图标也暂停排队。会话容量不足返回明确的 409 提示。写入和控制请求不会自动重放。

- 显式开启伴随屏时恢复本安装已有的隐藏天气、性能、音量和专注采集，不开启可见桌面卡片或新增登录启动。天气显示实际成功获取时间；系统磁盘容量直接读本机系统盘。源缺失或未恢复时保留明确原因。
- 电脑选择允许的应用，网页复用分类、文件夹和排序，以随机 ID 请求在电脑操作。网页不接收应用路径或命令行。通过校验后复用桌面 Dock 的打开逻辑：未打开时启动，后台窗口切到前台，前台再次点击则最小化；存在多个窗口时在电脑选择窗口。提示表示请求已提交，不承诺所有应用均接受前台切换。
- 配对时分别选择应用、音乐、桌面外观/音量/专注/快捷控制、私人待办、私人笔记、触控板、屏幕画面、键盘输入和电源控制权限；默认都不选。新增权限独立控制，旧配对记录升级后仍默认关闭。电脑管理窗以蓝灰色设备区展示已授权设备与待批准请求；唯一设备会自动选中，勾选权限后点击 **保存设备权限** 才生效。刷新与切换设备保留当前窗口的编辑草稿，不自动保存或批准。无需解除配对；旧控制租约和未执行的电源任务会随权限更新失效。应用共享范围单独整理，最多 500 项；连接配置与二维码按需展开。
- 待办和笔记保存在电脑现有文件中，共用桌面写锁。冲突返回 409，保留草稿，需重新载入并合并；不会静默覆盖。笔记沿用 32768 字符/读取 128 KB 限制和单份 `.previous` 恢复文件。
- 在电脑控制中心进入 **桌面与歌词**，可修改 Sky/Astro 主题、玻璃浓度、文字大小、Dock 图标与自动隐藏、应用列数与名称、左右组件显示及暂停策略。点击 **保存桌面设置** 才写入电脑现有配置，使用同一写锁和修订号；电脑同时修改时保留调整并提示载入电脑版本。不会开放显示器硬件标识、路径或快捷键配置。iPad 的“本页减少动画”仍只影响本页，不解除电脑其他暂停原因。
- 歌词复用电脑的字体风格、排版、颜色、文字材质、换句动效、背景配色与暂停/间奏状态；iPad 使用系统可用字体并适配屏幕字号。获得音乐与控制两项权限后，可在 **歌词光影** 调整并保存效果。样式有独立修订号与冲突检查，只修改外观，不改歌词显示开关、联网偏好、时间偏移或间奏偏好；坏文件不会用默认值覆盖。封面和壁纸只共享提取的配色，不传本地文件路径。
- 伴随屏开启期间可独立采集当前音乐元数据，关闭桌面歌词不再令歌曲信息一起消失；歌词显示和联网仍遵从原开关。没有新鲜媒体采样就停止显示旧歌词。媒体按钮发送系统媒体键，实际作用于哪个播放器由 Windows 决定。
- **电脑控制中心** 集中提供音量滑条、专注、电脑状态、窗口切换和电源入口。音量只接受 0–100 的整数且要求音量采集可用；按 [Win7Audio 的行为](https://docs.rainmeter.net/manual/plugins/win7audio/)，设置音量会解除静音。窗口操作仅允许切换窗口、任务视图、显示桌面、最大化、还原/最小化及前后虚拟桌面切换，发送前再次校验前台上下文，不能提交任意按键或命令。还原/最小化沿用 Win+Down 行为；不自动创建虚拟桌面。
- **手边的小美好** 提供本地倒计时、秒表、四则计算器、日期距离、世界时钟和呼吸节奏，以及按权限显示的天气、待办摘要和沉浸入口，共九种。可整理顺序与可见性；仅把卡片偏好、默认时长和时区保存在 Safari 本地，不保存电脑内容、计算过程或所选日期。升级保留原有卡片选择，可从“整理小组件”打开新增卡片。未配对也能先用本地工具；页面重新载入会重置运行中的本地计时，后台节流或关闭页面时不能作为系统闹钟。
- Touch Bar 可点击 **固定此场景** 保留当前布局，再点 **恢复跟随** 返回自动切换。沉浸展示可切换 **时钟与音乐、歌词舞台、安静时钟**；歌词舞台复用现有歌词效果和电脑真实内容，未共享音乐时回到时钟。布局切换不向电脑发送操作。

## 蓝灰氛围与光学玻璃

[初始概念图](media/concepts/companion-optical-20261026.png)用于说明构图、材质和信息层级，是设计概念，不是真实运行截图或 iPad 性能证据。用户要求背景更克制后，生产背景改为低对比蓝灰柔光远景，去除大月亮、星点和密集云层；生成记录见[最终背景提示词](media/concepts/companion-scene-quiet-20261026.prompt.md)。

网页的音乐面板、专注胶囊和底部 Touch Bar 共用同一个场景渲染器，最多渲染三个重点玻璃区域。玻璃采样同一张蓝灰远景背景，按局部曲面偏移与放大场景，加入边缘反射和轻微色散；文字和按钮保持独立、清晰的网页元素。背景图片随程序提供，不依赖外部图片服务。

渲染上限为 30 帧/秒，限制画布像素并在持续慢帧时降低分辨率。切后台、未连接或开启“本页减少动画与模糊”时停止光学动画；WebGL 不可用或上下文丢失时回退到静态样式，功能仍可操作。上述限制是代码策略，iPad Air 2 的实际 GPU 帧率、发热与耗电仍待设备验收。

可选屏幕画面、原生中文键盘的官方下载入口、建议安装路径、配置文件及实际限制见 [投屏安装与配置](COMPANION-SCREEN.md)。投屏需额外配置 FFmpeg、MediaMTX 和兼容 NVIDIA 编码器，不影响原有基础伴随屏功能。只有用户显式开启后才发送整块显示器画面；屏幕、键盘及触控权限分别保存。

## 触控板与电源

电脑授予 **触控板** 权限后，在 iPad 的触控板页点击启用：单指移动电脑鼠标，单指轻点发送左键，双击按住可拖拽，双指轻点发送右键，双指上下移动滚动；也可使用明确的左键、右键按钮。右侧独立 **滚轮** 区支持单指上下滑动、上下单格按钮及方向键/PageUp/PageDown，沿用同一输入通道和自然滚动方向。灵敏度和自然滚动可在本页调整。松手、停止控制、租约失效或撤权时释放本程序持有的鼠标按钮。鼠标作用于电脑当前桌面；系统安全界面或权限更高的窗口可能拒绝输入。

一次只允许一个设备持有触控租约，20 秒无有效输入会过期。每包按序号去重，移动和滚动有幅度限制；离开触控页、后台或断线时本页停止发送，旧输入不会在恢复连接后重放。

移动按 17 毫秒合并发送，目标约 59 次/秒；只保留一个在途请求，超过 200 毫秒的待发移动丢弃，微小位移保留余数。指针使用独立预算（设备 90 次/秒、5400 次/分钟；IP 180 次/秒、10800 次/分钟），不占用应用和设置通道。实际流畅度取决于 Wi-Fi 延迟与 Safari 调度，发送目标不等于真机测得帧率。拖拽期间每 250 毫秒保活，心跳中断后电脑自动释放；释放失败会继续尝试并拒绝新租约。

**电源控制** 单独授权。选择操作后会出现确认框，确认在 30 秒内有效；再次确认后进入以下倒计时，期间可点击取消：

| 操作 | 提交给 Windows 前的倒计时 |
|---|---|
| 锁定 | 3 秒 |
| 睡眠 | 5 秒 |
| 重启、关机 | 15 秒 |

倒计时由 PrismGlass 保存在内存中。取消仅影响本程序尚未执行的任务；关闭伴随屏、撤销或更新权限、锁屏都会取消等待中的任务。普通断网不保证取消已确认的任务，结果未知时应先在电脑核对，页面不会自动重新提交。关机与重启不强制关闭应用；界面显示“已提交给 Windows”表示系统接受请求，不能证明电脑已完成关机或睡眠。权限不足和系统拒绝会显示失败原因，不自动提权。

**开机 / 远程唤醒（Wake-on-LAN）尚未配置。** 关机后本机网页服务也会停止，不能自行唤醒这台电脑；本轮没有改动网卡或固件的唤醒设置。

## 首次部署

普通用户从电脑托盘打开 **iPad 伴随屏**，未配置时会显示 **连接步骤**。电脑端使用 Windows 自带 PowerShell 5.1，无需另装 PowerShell 7；打开窗口或阅读步骤不会开启网络服务。

1. 让电脑和 iPad 连接同一家庭 Wi-Fi 或个人热点，点击 **检查并连接**。程序自动选择可用网卡；需要改地址或端口时展开 **连接设置**。公共网络会先询问是否将这个网络设为专用，不会自动信任陌生网络。
2. 检查通过后，窗口列出固定 HTTPS 入口和实际改动。确认并通过 Windows 管理员提示后，才会创建专用 CA、固定名称证书、当前用户访问权限及限定网卡、专用网络和本地子网的规则。CA 有效期三年，服务证书一年，私钥不可导出；不会修改 Windows 根证书信任。全新安装不再要求一个不存在的旧配置文件。
3. 在 **连接步骤 → 导出 iPad 证书** 保存 `PrismGlass-Companion-CA.cer`，通过你信任的方式传到 iPad。导出时核对本安装记录的证书指纹与 CA 身份，只导出公开证书，不含私钥。不要发送整个程序或运行数据目录。
4. 在 iPad 安装这份证书的描述文件，再打开 **设置 → 通用 → 关于本机 → 证书信任设置**，为刚安装的 PrismGlass 证书开启完全信任。此步骤必须在 iPad 手动完成；不要忽略 Safari 证书错误，也不要信任来源不明的证书。见 [Apple 官方说明](https://support.apple.com/en-us/102390)。
5. 在电脑点击 **开启并生成配对二维码**。先用 iPad Safari 打开入口，再通过分享菜单 **添加到主屏幕**；关闭 Safari，从主屏幕图标打开后，用页面内 **扫码配对** 扫描电脑二维码，或手动输入配对码。回到电脑核对设备名称、选择需要的权限并批准。Safari 与主屏幕窗口的配对会话相互独立，所有权限默认不选。
6. 以后从 iPad 主屏幕打开即可；每次电脑重新启动 PrismGlass 后，先点 **检查并连接**。设备会话在有效期内无需反复输入码；换网、证书到期或清除网页数据后按窗口提示处理。

已配置过旧版而尚无固定名称记录的用户，在 **连接步骤 → 导入旧连接配置** 选择原来的 `setup-record.json`，沿用 iPad 已信任的 CA。已有本安装的网络记录时会直接复用，不允许以首次配置覆盖旧 CA、权限或配对。

首次配置也采用先预览、再明确批准、最后读回保存记录的流程；失败时仅回滚这次新建且归属仍匹配的对象。无法确认 HTTPS 绑定已移除时保留其证书并报错，不继续声称配置成功。图形检查与隔离测试不代表 iPad 已完成证书信任或触控验收。

### 旧 IP 入口的手动配置

以下保留给维护旧部署的用户。新安装请使用上方图形流程，不需要自行输入脚本参数。准备构建与部署是两项操作，先审阅脚本预览，再批准系统改动。

1. 将准备包放到正式安装位置，完成 PrismGlass 原有安装/升级。保持 iPad 和电脑处于同一可信局域网。
2. 在电脑设置 → iPad 伴随屏中选取实际的私有 IPv4 地址，记下端口（默认 9443）。建议路由器为电脑保留地址；地址改变后，证书 SAN 和绑定也需重新配置。
3. 使用 PowerShell 7 或系统自带的 Windows PowerShell 5.1 预览，地址必须是本机已有的 **Private** 网络；脚本不会改变网络类别：

   ```powershell
   ./ConfigureCompanion.ps1 -Address '<本机私有 IPv4>' -Port 9443 -User '<电脑名\普通用户名>' -OutputDirectory '.\companion-setup'
   ```

   地址、用户、路径是示例，必须替换为实际值。`-User` 必填，填写平时运行 PrismGlass 的普通 Windows 用户，不是临时使用的其他管理员账号。省略 `-Apply` 时只读检查并输出变更范围，不创建证书或网络规则。预览核对端口上的所有 SSL 绑定、URL 保留和监听；查询失败就停止，需要选择完全空闲的端口。

4. 审阅并明确批准后，以管理员 PowerShell 7 或 Windows PowerShell 5.1 执行同一命令加 `-Apply`。脚本创建专用 CA 和一年有效的 IP SAN 服务证书、精确地址的 HTTP.sys SSL/URL ACL，以及仅选中网卡、Private、本地子网、目标地址和 TCP 端口的规则。密钥不可导出；不会修改 Windows 受信任根目录，不会自动启动服务。现有绑定、规则或输出目录会使操作停止，不会被替换。
5. 将输出的公开 `PrismGlass-Companion-CA.cer` 通过你选择的可信方式传给 iPad。仅传证书，不传密钥或整个运行数据目录。在 iPad 安装证书描述文件，并在“设置 → 通用 → 关于本机 → 证书信任设置”中明确启用这份证书的完全信任。需要在设备上人工完成；不要信任来源不明的证书。
6. 回到电脑伴随屏窗口，保存允许的应用范围，点击“开启并生成配对二维码”；这次手动点击会开启尚未运行的服务并生成二维码，不会增加自动启动。用 iPad 相机扫描后在 Safari 打开，配对码会自动填入；点击“请求配对”。也可手动输入或粘贴六位配对码。在电脑核对设备名称，选择权限并批准；只有一个待批准请求时会自动选中，但不会自动批准。二维码由随包附带的 QRCoder 在本机生成，不调用外部二维码服务；短期配对码只放在 URL 片段中，页面读取后立即移除，不作为查询参数传给服务器。
7. 如需主屏幕入口，建议先在 Safari“添加到主屏幕”，随后从图标打开，点击页面内 **扫码配对** 扫描电脑二维码，在这个窗口完成配对。Safari 的已配对状态不会转移到主屏幕独立窗口；两边各自保留会话。普通 Safari 也可独立使用。Air 2 不依赖网页常亮接口，想常亮时自行调整设备自动锁定设置。

系统配置依据：[Microsoft HTTP.sys/netsh](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/netsh-http)、[Microsoft New-SelfSignedCertificate](https://learn.microsoft.com/en-us/powershell/module/pki/new-selfsignedcertificate)。脚本执行后需要读回绑定并实测 HTTPS；配置输出不等于端到端成功。

失败时仅尝试回滚本次创建且归属仍匹配的对象，输出目录保留失败记录；SSL 绑定删除未确认时保留证书以便恢复。不要把失败配置目录中的 CA 导入 iPad。iPad 手动信任步骤见 [Apple 官方说明](https://support.apple.com/en-us/102390)。

## 固定入口与换网

已完成首次 CA 安装的设备，可使用电脑管理窗显示的固定入口，形式为 `https://<你配置的固定名称>:9443/`；占位内容必须替换为自己的配置，不要照抄示例。电脑托盘 → **iPad 伴随屏** → **检查并连接** 会重新读取当前地址，检查证书、访问权限和防火墙；系统变更先显示范围，再请求管理员确认。旧版初次迁移通过 **导入旧连接配置** 选择原来的 `setup-record.json`；之后使用本安装 `runtime-data/companion-network.json`，不重复选择或重新安装 CA。

- 固定名称只在手动开启期间发布，限定当前网卡：Windows 发布服务记录，伴随屏内置的受限 mDNS 模块只回答这一条名称的 IPv4 地址。HTTPS 使用精确名称和 SNI 绑定，仍检查请求到达的本机地址。防火墙仅允许选定网卡、专用网络、本地子网、TCP 9443；此网卡的本机地址可变化。另有仅允许本安装 `LiquidDesktop.exe`、相同网卡/Private/LocalSubnet 的 UDP 5353 入站规则，用于固定名称发现；不开放通用 DNS 转发。
- 同一已配置网卡换 IP 后，点 **检查并连接** 即可重新识别地址；固定名称和证书不变。更换网卡、证书到期或公共网络需要再次审阅配置。不会自动把陌生网络改成专用。
- 视频规则单独按当前已授权 iPad 的真实地址检查。开始投屏时若规则过期，电脑会显示修复范围；确认后自动更新，iPad 等待并继续连接，不用手动改 IP。详情见 [投屏连接修复](COMPANION-SCREEN.md)。
- **检查并连接** 显示不含配对码的固定入口二维码；**开启并生成配对二维码** 用于新设备或首次迁移。IP 入口与固定名称属于不同网页来源，因此首次迁移仍需配对；原设备记录、应用范围和共享权限保留。
- iPad 在 Safari 打开固定入口后，分享 → **添加到主屏幕**，然后关闭 Safari，从主屏幕图标打开。首次在这个窗口点击 **扫码配对**，允许相机后扫描电脑的配对二维码，自动提交请求；在电脑核对名称并批准。相机画面只由随包附带的 jsQR 在本机处理，识别、取消、切后台或 60 秒到时关闭；不上传、不保存、不跳到 Safari，也不接受其他地址的配对码。无法使用相机时保留手动输入。
- 同一主屏幕窗口会记住已批准设备，先恢复会话，再决定是否显示配对输入。有效会话每日至多续期一次至 30 天，连续 30 天未使用、主动撤销或清除网站数据后需要重新配对。不会通过 IP 或设备名称自动信任陌生设备。无离线私人数据缓存，也不新增 iPad 安装包；首次完成后日常不需扫码或输入 IP。
- 电脑与 iPad 必须能在局域网互访；访客网络、热点客户端隔离或禁用 mDNS 会阻断发现。公网远程连接不在本功能范围内。
- `LiquidDesktop.exe --companion` 打开已运行 PrismGlass 的管理窗，不会自动启用服务。关闭服务、地址/网络变化会停止控制和发现，需手动重新连接；不重放旧操作。

命令行预览工具为 `RepairCompanion.ps1`（Windows PowerShell 5.1 或 PowerShell 7）。电脑管理窗优先使用系统目录内的 5.1；系统组件不可用时才尝试已验证的 7，不要求另行安装。必需参数为 `-AppRoot -Address -InterfaceIndex -HostName -UserSid`；全新配置显式传 `-Initialize`，旧版迁移传 `-ExistingSetupRecord`，两者不能同时使用或覆盖已有记录；默认端口 9443。省略 `-Apply` 只读检查并返回 JSON；`-TrustNetwork` 只在明确同意将当前公共网络改为专用时传入。修复时沿用已记录的 CA，不改 Windows 根信任，保留旧 IP 配置；只创建或更新归属与范围核验成功的固定名称配置。配置成功不等于 mDNS 或 iPad 已验收。
## 撤销、关闭与故障

- 在电脑选择设备 → 撤销，立即拒绝旧会话；网页也可退出配对。最多 8 个设备，会话在持续使用时续期，30 天未使用失效。重启后仍需手动开启入口。
- 关闭服务或退出 PrismGlass 后没有伴随屏监听。Windows 锁屏、登录安全桌面和权限丢失时拒绝控制和私人数据；解锁后重新同步。
- 配对入口码和待批准请求各有两分钟有效期。重新生成入口码不会清除已经提交的有效请求；批准后保留至少 30 秒供 iPad 领取结果。页面会明确提示等待和过期，手动输入不会被后台连接检查清空。关闭服务、锁屏或明确拒绝仍会终止待处理请求。
- 网页切后台停止轮询并清空私人视图；断线/超时遮蔽私人数据并禁用控制。未保存的待办和笔记编辑仅暂存在当前页面内存，重连并重新验证共享权限后恢复，保留原修订号以检查冲突；后台、锁屏、退出或重新配对会清除暂存。不会离线排队或自动重试写入、切歌或启动命令。请求超时可能意味着命令已执行，先检查电脑再决定是否再次操作。
- 网络恢复且授权重新验证后，回到原页面并恢复固定场景。浏览器离线、电脑返回锁屏状态分别提示；服务没有响应时不能可靠区分电脑休眠、服务关闭与网络隔离，因此提示检查电脑和局域网，不猜测具体原因。
- 数据源未运行时，可在电脑伴随屏窗口再次点“检查并连接”恢复采集；它只操作输出目录匹配、配置为隐藏的已安装采集皮肤。不会启动尚未运行的 Rainmeter。关闭的歌词显示/联网开关不会因为 iPad 重连而改变。
- 旧 IP 入口的证书到期、IP 改变或网络变成 Public 时需重新审阅配置；固定入口仅 IP 改变不需新证书；不要扩大到所有地址、所有网络或公网。脚本不会自动清理旧绑定；保留 `setup-record.json` 用于精确识别要撤销的证书、URL ACL 和规则。
- 配对数据使用 Windows 当前用户 DPAPI 保护。更换 Windows 用户无法复用旧记录。不要将配对数据提交、打包或复制给别的用户。

2026-10-26 复核发现分类/搜索仍会重建图片且绕过冷却，图片和核心 API 共用预算及 Bridge 等待锁会放大影响；本次增加图片队列与缓存、独立预算和不等待 UI 的只读资产快照。旧 iPad 现场的确切拒绝类别没有历史日志，不能将代码复现等同于现场流量测量。电脑状态中的诊断只保留各类拒绝次数及时间，不含 IP、凭据、请求体或私人内容。

前台快捷键通过 Windows SendInput 提交，权限低于目标程序时可能被系统拒绝；发送前检查窗口身份及当前按住的修饰键，不激活窗口、不接受任意按键序列。Windows 不提供原子绑定前台的 SendInput 操作，因此不要在操作 iPad 按钮的同时刻主动切换电脑窗口。参见 [Microsoft SendInput 说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)。

## 存储、范围与验收

网页使用系统字体，蓝灰远景图片作为随包静态页面资源加载，无媒体库下载、Service Worker 或业务数据库。电脑业务数据保留在电脑，网页只持有会话及当前视图；小组件只在本地保存上述非私人偏好，浏览器自身缓存仍由 Safari 管理。清除网站数据会清除本地偏好并需要重新配对，电脑已保存内容不变。
